# P4-B 板端验收速查（PWM 蜂鸣器 + I2C 环境光 AP3216C + SPI 六轴 ICM20608）

> 配套《项目进度.md》P4-B 验收 + 手册 5.13.4 PWM 项。
> 前置：Ubuntu `make && make send` 编译成功（dts/ko 无报错）、dts 生效（TFTP 或刷写后重启）、驱动已加载（`insmod beep_pwm.ko`）。
> 硬件：**无源蜂鸣器** 正极→GPIO1_IO04（PWM3_OUT，官方引脚）、负极→GND。（板载蜂鸣器是有源的 GPIO5_IO01，与本驱动无关）
> 设备节点：`/dev/beep_pwm0`；测试程序：`beep_test`（--freq/--duty/--on/--off）。

## 一键验收脚本（推荐）

`test/P4_accept.sh` 自动执行 ①~⑤ 五步（含听感交互确认），输出 PASS/FAIL 汇总。

```bash
# 拷贝到测试程序所在目录并执行
cp ~/shared/win-share/imx6ull-drivers/core/beep_pwm/test/P4_accept.sh .
chmod +x P4_accept.sh
./P4_accept.sh
```

> 脚本末尾会自动 `rmmod beep_pwm`（验收⑤）。如需继续测试，按提示重新 `insmod`。

## ①' dts 生效确认（重编 dts 后必查）

```bash
cat /sys/kernel/debug/pinctrl/pinctrl-handles
# 找 device: 2088000.pwm 段，应见:
#   group: pwm3grp
#   pin MX6UL_PAD_GPIO1_IO04 (27) 000110b0
```

**通过标准**：`2088000.pwm → pwm3grp → MX6UL_PAD_GPIO1_IO04 (27) 000110b0`——即官方宏在板端生效，PWM3 信号在 GPIO1_IO04。
**若仍显示 GPIO1_IO10 / 其他引脚**：dts 未重编或未生效（旧 dtb 仍在跑），回去确认 `make dtbs` + TFTP/刷写 + 重启。
> 2026-08-19 实测：此命令确认 pwm3grp 已配到 GPIO1_IO04，根因修复生效。（注意 IO04 是 pin 27，IO10 是 JTAG_MOD 引脚，不在 PWM 配置中）

## ② 频率可控（500Hz 低沉 → 2000Hz 尖锐）

```bash

```

**验收通过标准**：两声明显音调不同（500→2000Hz 变高尖锐）；ioctl 无报错。

## ③ 占空比可控（50% 响 → 10% 小声 → 0% 静音）

```bash

**验收通过标准**：50%→10% 声音明显变小；duty=0 静音（enabled 自动关闭）。

```

**验收通过标准**：--off 立即静音；--on 恢复同频同占空比鸣响。

## 异常排查

| 现象 | 排查 |
|---|---|
| insmod 报 `unknown symbol` / probe 失败 | dmesg 看 pwm_get 失败原因（PWM3 是否被占用/未使能） |
| 编译 dts 报宏未定义 | 确认用的是官方宏 `MX6UL_PAD_GPIO1_IO04__PWM3_OUT`（imx6ul-pinfunc.h L112 已定义，mux=0x006C, ALT1）；若误用 `MX6UL_PAD_GPIO1_IO10__PWM3_OUT` 会报错（该宏不存在——GPIO1_IO10 无 PWM 功能），贴回报错行 |
| 无声音 | 确认**无源蜂鸣器**（有源蜂鸣器内部自带振荡，接 PWM 也不按 freq 响）、正负极接线、`--on` 或 duty>0 |
| 有声音但所有模式一样（音调/响度不随 freq/duty 变化） | 接的是**有源蜂鸣器**（内部振荡器决定频率，PWM freq/duty 无效）——须换**无源蜂鸣器**（正极→GPIO1_IO04、负极→GND）；板载蜂鸣器（GPIO5_IO01）是有源的，与本驱动无关 |
| 换无源蜂鸣器后不响 | 确认接的是 **GPIO1_IO04（PWM3_OUT 官方引脚）**，而非 GPIO1_IO10（JTAG_MOD，非 PWM 引脚，曾误配导致无信号）；GPIO1_IO04 直驱电流可能不足（无源蜂鸣器需数十 mA 级驱动，建议加三极管/MOS 放大）；确认正负极、接触、模块未损坏 |
| LED 接 GPIO1_IO10 常亮/不随命令变化 | **接线引脚错误**：GPIO1_IO10 是 JTAG_MOD 引脚（mux=0x0044, ALT5），不是 PWM3_OUT！PWM3_OUT 官方引脚是 **GPIO1_IO04**（NXP SDK evkmcimx6ull/pwm/pin_mux.c 确认 pin M16）。早期 dts 曾误配 GPIO1_IO10（0x0084 推断值）致 PWM 信号未输出，已修正为 `MX6UL_PAD_GPIO1_IO04__PWM3_OUT`。LED 改接 GPIO1_IO04 + GND 后重测 |
| LED 闪烁正常但 `--off` 后全亮 | **接法方向错误（低电平点亮）**：LED 负极接引脚 + 正极接 5V 时，PWM 高电平(3.3V)使 LED 反偏不亮、低电平(0V)点亮，`--off` 拉低引脚 → LED 全亮，属正常物理现象非驱动 bug。改高电平点亮接法：**LED 正极串 1kΩ → GPIO1_IO04、负极 → GND**，`--off` 拉低引脚 → LED 熄灭 |
| 声音异常/抖动 | 频率超 20kHz 被拒（EINVAL）；占空比 0~100 边界 |
| 疑问：驱动频率范围 1Hz~20kHz 硬件能否支持？ | 支持。内核 4.1.15 pwm-imx.c v2 `imx_pwm_config_v2` 对 period 超出 16 位计数（65536）时自动 `prescale = period_cycles/0x10000+1` 分频（12 位 prescale），全频段不报错；LED 验证低频可用 `--on --freq 1 --duty 50`（应 1Hz 闪烁） |

# P4-B I2C：AP3216C 环境光/接近传感器

> 配套《项目进度.md》P4-B 验收 + 手册 5.13.4 I2C 项。
> 前置：`insmod ap3216c.ko` 成功（dmesg 见 `AP3216C ready`）；测试程序 `ap3216c_test` 已就位。
> 硬件：**板载于 I2C1（器件地址 0x1E），无需接线**。传感器小窗口在板上（透过小孔可看到灯芯）。
> 设备节点：`/dev/ap3216c0`；测试程序：`ap3216c_test [次数]`（默认每秒一读，无限循环）。
> ★寄存器勘误：手册 5.13.2 骨架中 PS 寄存器写 0x10 系笔误，实际为 0x0E/0x0F（与正点原子/datasheet 一致），驱动已按正确地址实现。

## ① 设备节点

```bash
insmod ap3216c.ko
ls -l /dev/ap3216c0
dmesg | tail -5
```

**验收通过标准**：`/dev/ap3216c0` 存在；dmesg 出现 `AP3216C ready`，无 probe 失败。

## ② 正常读数（光照响应）

```bash
./ap3216c_test 5    # 每秒打印 ir/als/ps，共 5 次
```

**验收通过标准**：三列读数正常输出（非 0）；用手电照传感器 als 明显变大，移开后回落。

## ③ 遮挡响应（距离）

```bash
./ap3216c_test 8
# 运行期间用手指贴近传感器小窗口 2~3 秒再移开
```

**验收通过标准**：手指贴近时 `ps` 明显变大（越大越近），移开后回落；期间 `ir`/`als` 正常。

## ④ 硬件层验证

```bash
i2cdetect -y 1             # I2C1 总线扫描（默认 quick-write 模式）
i2cdump -y 1 0x1e          # 读 AP3216C 寄存器（0x00 应为 0x03）
```

**验收通过标准**：`i2cdetect` 输出在 `0x1e` 处显示地址；`i2cdump` 首行可见寄存器值（0x00=0x03 使能态）。
> 注意：`i2cdetect -y -r 1`（SMBus read-byte 模式）扫不到 0x1e 属正常——AP3216C 对不带寄存器地址的 read-byte 探测不应答；驱动能读到数据即通信正常。

## ⑤ rmmod 干净卸载（五件套）

```bash
fuser /dev/ap3216c0 2>/dev/null; echo "fuser exit: $?（1=无占用）"
rmmod ap3216c
ls /dev/ap3216c0 2>&1           # 应报 No such file
lsmod | grep ap3216c            # 应无输出
dmesg | tail -5                 # 无警告/无泄漏
```

**验收通过标准**：rmmod 无报错；`/dev/ap3216c0` 消失；lsmod 无残留；dmesg 干净。

## 异常排查

| 现象 | 排查 |
|---|---|
| insmod 报 `chip init failed` | I2C 通信失败：确认 i2c1 已使能（`i2cdetect` 能扫到 0x1e）；板载器件是否焊好 |
| 读数全 0 | 溢出标志置位（IR.bit7 / PS.bit6）：遮挡过近或光照过强，属正常保护；`i2cdump` 验证寄存器 |
| 读数交替全 0（0/正常/0/正常） | 曾因一次连续读 0x0A~0x0F 6 字节导致数据帧交替失效，已改为与正点原子一致的逐字节读；若仍出现，检查两次读取间隔是否 <112.5ms（同时开 ALS+PS 的数据更新周期） |
| `/dev/ap3216c0` 不存在 | dmesg 看 misc 注册是否失败；确认 insmod 无报错 |
| als 一直不变/恒 0 且 ps 大增（如 500+） | **传感器窗口被遮挡**：检查 AP3216C 小窗口有无贴纸/异物；移开遮挡后 als 恢复非 0、ps 回落小值；用手遮挡/移开可验证 ps 响应 |

# P4-B SPI：ICM20608 六轴 IMU

> 配套《项目进度.md》P4-B 验收 + 手册 5.13.4 SPI 项。
> 前置：`insmod icm20608.ko` 成功（dmesg 见 `ICM20608 WHO_AM_I = 0xaf` + `ICM20608 ready`）；测试程序 `icm20608_test` 已就位。
> 硬件：**板载于 ECSPI3（dts: icm20608@0，8MHz），无需接线**。芯片在板上（靠近 SPI Flash/背面）。
> 设备节点：`/dev/icm20608`；测试程序：`icm20608_test [--num N]`（默认每秒一读）。
> 量程：±16G / ±2000dps；换算见 uapi/icm20608.h（加速度 g、角速度 dps、温度 ℃）。

## ① 设备节点

```bash
insmod icm20608.ko
ls -l /dev/icm20608
dmesg | tail -5
```

**验收通过标准**：`/dev/icm20608` 存在；dmesg 出现 `ICM20608 WHO_AM_I = 0xaf`（芯片校验通过）+ `ICM20608 ready`，无 probe 失败。

## ② 静止读数（六轴合理性）

```bash
./icm20608_test --num 10    # 每秒一组，共 10 组
```

**验收通过标准**（手册 5.13.4）：
- `accel.z ≈ +1.0g`（重力方向），`accel.x/y ≈ 0`
- `gyro` 三轴 ≈ 0（静止无转动）
- `temp ≈ 36℃` 上下（**芯片真实温度**：板载 IMU 受核心板热量传导，实测 36.6℃ 稳定，非室温；若手摸芯片会更高）
- **测试期间保持板子静止平放**——手持/晃动会读到 gyro 大幅非 0、accel 超 1g，属正常动态响应而非故障

## ③ 动态响应

```bash
./icm20608_test --num 10
# 运行期间拿起板子缓慢翻转/晃动 2~3 秒再放平
```

**验收通过标准**：晃动时 `gyro` 三轴出现明显非 0 值，`accel` 分量随板姿变化（重力分量在 x/y/z 间重新分配）；放平后回到 ② 状态。

## ④ 硬件层验证（WHO_AM_I）

dmesg 中的 `ICM20608 WHO_AM_I = 0xaf` 即硬件层验证（手册验收项"读出 WHO_AM_I=0xAF"）。
若显示 `0xae` 为 ICM20608D 变体，同样有效；若 mismatch 报错则 SPI 通信异常。

## ⑤ rmmod 干净卸载（五件套）

```bash

rmmod icm20608
ls /dev/icm20608 2>&1           # 应报 No such file
lsmod | grep icm20608           # 应无输出
dmesg | tail -5                 # 无警告/无泄漏
```

**验收通过标准**：rmmod 无报错；`/dev/icm20608` 消失；lsmod 无残留；dmesg 干净。

## 异常排查

| 现象 | 排查 |
|---|---|
| insmod 报 `WHO_AM_I mismatch` | SPI 通信异常：确认 ECSPI3 引脚（UART2 复用）dts 已配、`i2cdetect` 无关；贴回 dmesg |
| probe 失败但 WHO_AM_I 正常 | 量程配置写失败：`icm20608_write_reg` 返回错误会在 dmesg 显示，贴回信息 |
| 读数恒 0 | 芯片睡眠（PWR_MGMT_1 复位后未上电？）；重新 insmod；dmesg 看配置序列 |
| 静止测试时读数大幅变化（gyro 上百 dps、accel 超 1g） | 板子在动（手持/晃动）——动态响应正常；平放置稳后重测 |
| accel.z 不是 1.0g | 板子未放平（有倾斜角）；或量程漂移，属正常范围（±0.1g 内） |
| 静止时出现固定异常值（如 accel.x≈+1.9g、gyro.z≈+123dps 恒定） | **解算顺序错位**：0x3B 起寄存器顺序为 accel_x,y,z/temp/gyro_x,y,z，read 输出必须重排为 gyro_x,y,z/accel_x,y,z/temp（正点原子 icm20608.c 的 readdata 有同款重排）；曾因驱动未重排误判为读法/硬件问题 |
