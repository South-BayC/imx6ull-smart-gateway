## ③ 三模式交互验证（block / nonblock / poll）

各模式跑 3~5 秒，交替按 KEY0 + 碰触 pin17-**VCC3.3**，确认 **ch=0 与 ch=1 都出现、事件成对**（按下/松开各一条），Ctrl-C 退出。

```bash
# 阻塞模式
./edt_capture_test

# 非阻塞模式
./edt_capture_test --nonblock

# poll 模式
./edt_capture_test --poll
```

**验收通过标准**：三种模式均能读到 ch=0（KEY0）与 ch=1（pin17）的事件；edge 值随电平变化（0=下降 1=上升）；Ctrl-C 后再次运行任一模式不报 EBUSY（release 自动 STOP 生效）。

## ④ 序列号守恒（queued+dropped == irq+snapshot）跨进程跨模式

```bash
# 跑 10 秒交互（任意模式，边跑边按键+碰触 pin17-VCC3.3），然后 Ctrl-C
./edt_capture_test --poll &
sleep 10
kill %1 2>/dev/null

# 读统计验证守恒：irq_events + snapshot_events == queued_events + dropped_events
./edt_capture_bench --duration 1 --report 1 2>&1 | grep 守恒
```

**验收通过标准**：bench 汇总打印 `守恒(irq+snapshot == queued+dropped): OK`；多次跨进程/跨模式连续运行后 sequence 仍连续递增（无回绕、无跳号）。

## ⑥ ftrace tracepoint 观测（4 个：irq/enqueue/drop/read）

```bash
# 挂载 debugfs + 打开事件（如已挂载可跳过）
mount -t debugfs none /sys/kernel/debug 2>/dev/null

# ★ 关键：IRQ handler 检查 running，running=0 时事件不 trace！
#   必须先启动任一模式让驱动 running（下面第 5 步再做）
#   开个后台 nonblock 测试进程即可：./edt_capture_test --nonblock >/dev/null 2>&1 &

# 打开 4 个 tracepoint
echo 1 > /sys/kernel/debug/tracing/events/edt_capture/edt_capture_irq/enable
echo 1 > /sys/kernel/debug/tracing/events/edt_capture/edt_capture_enqueue/enable
echo 1 > /sys/kernel/debug/tracing/events/edt_capture/edt_capture_drop/enable
echo 1 > /sys/kernel/debug/tracing/events/edt_capture/edt_capture_read/enable

# 清空并启动跟踪
echo > /sys/kernel/debug/tracing/trace
echo 1 > /sys/kernel/debug/tracing/tracing_on

# 按键 + 碰触 pin17（VCC3.3 或任一高电平针脚有效，GND 无效）若干次（产生事件）

# 停止并抓取
echo 0 > /sys/kernel/debug/tracing/tracing_on
cat /sys/kernel/debug/tracing/trace | head -60

# 收尾：关闭事件
echo 0 > /sys/kernel/debug/tracing/events/edt_capture/edt_capture_irq/enable
echo 0 > /sys/kernel/debug/tracing/events/edt_capture/edt_capture_enqueue/enable
echo 0 > /sys/kernel/debug/tracing/events/edt_capture/edt_capture_drop/enable
echo 0 > /sys/kernel/debug/tracing/events/edt_capture/edt_capture_read/enable
```

**验收通过标准**：trace 输出可见 `edt_capture_irq`（含 channel/level/timestamp）、`edt_capture_enqueue`（含 sequence/channel/fifo_len）、`edt_capture_read`（读后 fifo_len）；若触发溢出可见 `edt_capture_drop`（含 sequence/channel/fifo_len）。

## ⑦ rmmod 干净卸载


**验收通过标准**：rmmod 无报错；`/dev/edt_capture0` 消失；lsmod 无残留；dmesg 干净。

## P3-5 capture_bench 真机基准（手册 5.7.3 四指标）

```bash
# 默认 5s、每秒报告。运行期间持续按键 + 碰触 pin17（VCC3.3/高电平有效，GND 无效；或用信号源接 pin17）
```

**输出四指标**：交付事件率(ev/s)、丢失率(dropped/irq %)、交付年龄(age min/avg/max ms)、CPU 占用(%)。
**验收通过标准**：汇总守恒 OK；丢失率与激励频率相关（高速连按可出现合理丢失，FIFO=1024 事件）；CPU 占用低（poll 心跳 200ms，应 <5%）。
