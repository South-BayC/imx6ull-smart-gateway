# 第 1 章 项目总览

## 1.1 项目背景与目标

基于正点原子 I.MX6ULL ALPHA（EMMC 版）开发板，参考 6 个开源项目（remote_manage、plat-main 双项目、imx6ull_project、mmproject、FaceRecognition），设计两个真实贴合企业开发流程的嵌入式 Linux 项目，覆盖：

| 技术域 | 覆盖程度 |
|---|---|
| 企业级应用架构 | 守护进程模式、进程编排、IPC、状态机、配置校验、日志 |
| 边缘 AI 推理 | 双模推理：端侧 NCNN + 云端 GPU 推理，可切换、自动降级 |
| 网络通信 | MQTT、TCP 图像传输、HTTP（OTA）、心跳与重连 |
| 内核驱动 | 七大子系统：GPIO/IRQ/PWM/I2C/SPI/V4L2/input |
| 系统构建 | Buildroot 精简根文件系统、systemd、A/B 双分区 OTA |
| 界面交互 | Qt 5.9+ 触摸屏（7 寸 1024x600） |
| 工程化 | 单元测试、KUnit/kselftest、CI、诊断工具、文档与验收清单 |

## 1.2 硬件平台清单

### 已有设备
| 设备 | 型号 | 用途 |
|---|---|---|
| 开发板 | 正点原子 I.MX6ULL ALPHA **EMMC 版**（4GB eMMC） | 双项目主平台 |

### 采购清单（项目 A 需要）
| 器件 | 型号建议 | 用途 | 参考价 |
|---|---|---|---|
| 摄像头 | 正点原子 OV5640 摄像头模块（CSI 接口） | 视频采集 | 约 40-80 元 |
| 继电器模块 | 5V 单路继电器模块 | 告警联动（门锁/外设） | 约 3-10 元 |
| TF 卡 | 16GB Class10 | 数据扩展/升级包暂存 | 约 20-30 元 |
| 杜邦线/连接线 | 若干 | GPIO 外接 | 约 10 元 |

> 摄像头接线注意：直接插 CAMERA 接口，**勿用延长线**（信号干扰）；**不支持热插拔，插拔需断电**。
> A/B 双分区使用板载 eMMC，TF 卡用于升级包暂存与日志扩展，非必需但推荐。

### 开发板关键资源
- **CPU**：i.MX6ULL，Cortex-A7 单核 528MHz（无 NPU，端侧推理有限）
- **存储**：4GB eMMC（A/B 分区基础）
- **摄像头接口**：8-bit 并行 CSI（OV5640 使用）
- **GPIO/LED/蜂鸣器/按键**：板载若干（驱动项目载体）
- **I2C 传感器**：板载 AP3216C 环境光/距离传感器
- **SPI**：ECSPI 接口（可接 ICM20608 六轴 IMU）
- **网络**：百兆以太网

## 1.7 通用工程规范（双项目强制）

1. **代码风格**：统一 clang-format / kernel coding style（驱动项目）
2. **编译严谨**：`-Wall -Wextra -Werror`（应用）；内核驱动遵循 checkpatch.pl
3. **版本管理**：git 全程管理，每阶段打 tag
4. **文档先行**：每模块完成即写文档，不后补
5. **验收证据**：每个阶段验收项必须留证据（截图/日志/测试输出）
6. **不做假验证**：未实测的指标（FPS/事件率/稳定性）不写入文档

## 2.5 NFS / TFTP 开发模式（开发期快速迭代）

**NFS 根文件系统启动**（开发期最常用）：

```bash
# PC 端：配置 NFS
echo "/home/$USER/imx6ull/rootfs *(rw,sync,no_root_squash,no_subtree_check)" | sudo tee -a /etc/exports
sudo exportfs -ra

# 板端 U-Boot 启动参数（串口里，按板子 U-Boot 实际修改）
# 1. 先用 SD 卡/系统盘启动到 shell
# 2. 挂载 NFS rootfs（把正点原子出厂 rootfs 解压到 ~/imx6ull/rootfs）
# 3. 修改 U-Boot 环境 bootargs 为 nfsroot 方式，重启
setenv bootargs 'console=ttymxc0,115200 root=/dev/nfs nfsroot=192.168.1.100:/home/xxx/imx6ull/rootfs rw ip=192.168.1.101::192.168.1.1:255.255.255.0::eth0:off'
```

> 开发期常用：**U-Boot 网络引导内核（TFTP）** + **NFS rootfs**，应用改动直接复制到 rootfs 目录即生效，无需反复烧写。

## 2.8 驱动开发标准工作流（项目 B 每个驱动都走这套）

```
1. 写代码 xxx.c + Makefile
2. make KDIR=~/imx6ull/linux-imx6ull          # 编译 .ko
3. 拷到板子（NFS rootfs 或 scp）
4. 板端：insmod xxx.ko → 检查 /dev 节点与 dmesg
5. 运行用户态测试程序验证
6. rmmod xxx.ko → 检查资源释放（无泄漏/无 hung task）
7. 写文档 + 验收清单打勾
```

**通用模块 Makefile 模板**：

```makefile
# 每个驱动目录下的 Makefile
obj-m += xxx.o

KDIR ?= /lib/modules/$(shell uname -r)/build
all:
	make -C $(KDIR) M=$(PWD) modules
clean:
	make -C $(KDIR) M=$(PWD) clean
install:
	make -C $(KDIR) M=$(PWD) modules_install
```

> 交叉编译时：`make KDIR=~/imx6ull/linux-imx6ull ARCH=arm CROSS_COMPILE=arm-linux-gnueabihf-`

## 4.4 模块详细设计

### 4.4.1 gatewayd 主守护进程

**职责**：进程编排中枢，管理所有子服务生命周期。

**关键设计**：

```
gatewayd (主进程)
 ├── 启动子服务（fork + exec）：vision_service / cloud_agent / alert_service
 ├── 统一 IPC 服务端（Unix Domain Socket: /run/gateway/control.sock）
 ├── 子进程监督：SIGCHLD 处理、崩溃重启 + 指数退避
 ├── 配置加载与校验（启动时失败即退出）
 └── 优雅停机：SIGTERM → 通知各子服务 → 状态持久化 → 退出
```

**技术要点**：
1. **子进程监督**：崩溃自动重启，退避序列 1s→2s→4s→8s→上限 60s，连续崩溃超阈值进入"降级模式"（只保留 MQTT 上报）
2. **孤儿进程防护**：子服务启动时设置 `PR_SET_PDEATHSIG(SIGTERM)`，gatewayd 异常退出后子进程自动退出
3. **统一 IPC**：Unix Domain Socket，权限 0600，服务端校验对端 UID（SO_PEERCRED）
4. **启动失败策略**：配置缺失/非法 → fail fast；控制 socket 创建失败 → 启动失败
5. **systemd 托管**：`Type=simple`，`Restart=on-failure`，资源限制（MemoryMax/FilesMax）

**对外命令接口（JSON-RPC）**：

```json
{"jsonrpc":"2.0","method":"control","params":{"device":"led","action":"on"},"id":"uuid-1"}
{"jsonrpc":"2.0","method":"arm","params":{"mode":"arm_all"},"id":"uuid-2"}
{"jsonrpc":"2.0","method":"inference","params":{"backend":"cloud"},"id":"uuid-3"}
{"jsonrpc":"2.0","method":"get_status","params":{},"id":"uuid-4"}
{"jsonrpc":"2.0","method":"ota_start","params":{"url":"http://..."},"id":"uuid-5"}
```

### 4.4.2 vision_service 视觉服务（★双模推理）

**架构**：

```
┌──────────────────────────────────────────────────────────────┐
│ vision_service（独立进程）                                    │
│                                                              │
│  V4L2 采集线程 ──MMAP──> 帧缓冲池(有界环形) ──> 推理引擎       │
│      │                      │                                 │
│      │                      └─> 推理结果队列 ──> 结果消费者    │
│      │                              │                         │
│      └─> JPEG 编码线程（云端模式用）  └─> IPC 上报 gatewayd    │
│                                                              │
│  推理引擎接口（后端可切换）：                                  │
│   ├── local_engine  : NCNN 本地推理（离线可用）               │
│   └── cloud_engine  : 帧上传 PC → GPU 推理 → 结果回传         │
└──────────────────────────────────────────────────────────────┘
```

**V4L2 采集**：MMAP 模式 4 缓冲，YUYV→RGB 转换；默认 640x480（可配置）；FPS 按实际时间计算（非宣称值）；生产模式摄像头打开失败 → 进程报错退出（不静默降级）。

**帧缓冲池**：有界环形队列（默认 8 帧），满则丢最旧帧并计数。

**推理引擎统一接口**（双模共用关键抽象）：

```c
/* 检测目标 */
typedef struct {
    int    class_id;        /* 0=person 等 */
    float  confidence;
    int    x, y, w, h;      /* 归一化坐标 0-1000 */
    uint64_t timestamp_ns;
} det_result_t;

/* 推理后端接口 */
typedef struct inference_backend {
    int  (*infer)(void *ctx, const uint8_t *rgb, int w, int h,
                  det_result_t *out, int *count);
    int  (*get_status)(void *ctx, backend_status_t *status); /* 含延迟/帧率 */
    void (*destroy)(void *ctx);
} inference_backend_t;
```

### 4.4.3 cloud_agent 云端代理

**职责**：一切与云端的通信（MQTT 控制/状态 + TCP 推理帧 + 深度分析上传）。

**MQTT 状态机**（Paho）：

```
        ┌─────────┐   connect    ┌────────────┐   MQTT_CONNACK   ┌────────┐
        │DISCONNECTED│──────────▶│ CONNECTING │────────────────▶│ ONLINE │
        └─────────┘              └────────────┘                 └───┬────┘
              ▲                       │                              │ 掉线
              │                       │ 失败                        │
              │                       ▼                              ▼
              │                 ┌────────────┐                 ┌────────┐
              └────────────────│  BACKOFF   │◀────────────────│RETRYING│
                               └────────────┘                 └────────┘
```

- 重连：指数退避 + 抖动（2s→4s→8s→...→60s，±20% 随机），防重连风暴
- **Last Will**：遗嘱消息（`device/{id}/status` = offline），设备异常离线云端可知
- 重连后自动重订阅（订阅列表持久化）
- 回调只写入有界命令队列，业务线程消费

**TCP 帧通道**（推理用）：专用 TCP 长连接（与 MQTT 分离）；长度前缀 + 版本 + JPEG；往返延迟测量；结果回传 JSON（目标列表 + 延迟统计）。

**有界重试队列**：离线期间事件/告警入队（上限 100），恢复后按序补发。

### 4.4.4 alert_service 告警服务

**状态机**：

```
         ┌────────┐  布防指令    ┌─────────┐  检测到目标   ┌─────────┐
         │ DISARMED │──────────▶│  ARMED  │─────────────▶│ ALARMING │
         └────────┘             └─────────┘              └────┬────┘
              ▲                   │    ▲                     │ 告警超时
              │  撤防指令          │    │ 解除(远程/本地)      │
              └───────────────────┘    └─────────────────────┘
```

**告警判定配置**：灵敏度（置信度阈值默认 0.5）、目标大小过滤、夜间自动布防（配合环境光，P4 后）、目标类型过滤（只对 person）、连续帧确认（连续 N 帧才触发）。

**联动执行**（经 device_hal，不直接操作设备）：继电器闭合、LED 闪烁（1Hz）、蜂鸣器鸣响（PWM）、抓帧上传、MQTT 上报告警事件。

**状态持久化**：告警记录写日志文件（CRC 保护），含时间/类型/置信度/图片路径/处理状态。

### 4.4.5 ota_service 升级服务（A/B 双分区）

**eMMC 分区布局**：

```
mmcblk1p1  boot      （U-Boot + 环境变量）
mmcblk1p2  系统A     （内核 + 根文件系统）
mmcblk1p3  系统B     （内核 + 根文件系统）
mmcblk1p4  数据区    （配置/告警记录/媒体）
mmcblk1p5  OTA暂存   （升级包临时存放）
```

**升级流程**：

```
1. 触发（云端指令/界面/CLI）→ ota_service 从 HTTP 下载升级包到 /ota/ 暂存
2. SHA256 校验升级包（防损坏/篡改）
3. 解包校验（内核 + rootfs + 版本号 + 签名）
4. 写入非活动分区（从 A 启动 → 写 B）
5. 写入完成后全分区校验（hash 逐块比对）
6. 设置 U-Boot 环境变量 boot_partition=B，存储本次版本号
7. 重启 → 从 B 启动
8. 启动计数 +1；应用自检通过后上报"升级成功"（清计数）
9. 若连续 N 次启动失败（计数未清）→ U-Boot 自动切回 A
```

**企业级要点**：升级原子性（写另一分区，断电不影响当前系统）；回滚机制（启动计数 + U-Boot/应用双重保障）；版本管理 + 灰度发布；进度上报（MQTT）。

**升级包结构**：

```
ota_package_v1.2.bin
├── header      （magic + 版本 + 大小 + SHA256）
├── kernel.img  （zImage + dtb）
├── rootfs.img  （rootfs.ext4）
└── signature   （RSA 签名，可选）
```

### 4.4.6 device_hal 设备抽象层

**设计原则**：业务层不接触具体设备文件，全部经 HAL 封装。

```
device_hal/
├── hal.h               # 统一接口
├── hal_led.c           # LED 控制
├── hal_relay.c         # 继电器
├── hal_beep.c          # 蜂鸣器
├── hal_gpio_event.c    # 按键/事件采集（P5 后对接项目 B 驱动）
├── hal_sensor.c        # 环境光等传感器
└── hal_camera.c        # V4L2 封装
```

**演进策略**：P0~P4 用系统标准接口（V4L2、sysfs GPIO、PWM sysfs）；P5 后切换项目 B 自研驱动节点（/dev/edt_capture0、/dev/led 等），**接口不变只换实现**——这正是 HAL 的价值。提供 `--mock` 编译开关，无硬件时可跑业务逻辑测试。

### 4.4.7 IPC 层（Unix Domain Socket + JSON-RPC）

- 长度前缀（4 字节网络序）+ 协议版本（1 字节）+ JSON 载荷
- 载荷最大 4096 字节；字符串拒绝内嵌 NUL
- 连接、收发共用统一绝对截止时间（防死锁）
- socket 0600 权限 + SO_PEERCRED 校验
- 每次操作新 UUID；64 ID 去重窗口（防重放）
- JSON-RPC 子集：method/params/id/result/error；解析器深度 ≤16；未知字段拒绝

## 4.5 双模推理详细设计（★核心创新点）

### 为什么双模

| | 本地推理（NCNN） | 云端推理（GPU） |
|---|---|---|
| 算力 | Cortex-A7 单核，1-5 FPS | RTX GPU，30+ FPS |
| 精度 | 小模型（MobileNet-SSD） | 大模型（YOLOv8） |
| 延迟 | 无网络依赖 | 局域网 50-150ms/帧 |
| 可用性 | 离线可用 | 依赖网络 |
| 成本 | 无 | 需 PC + 网络 |

**真实产品中**：边缘推理用于离线兜底/低延迟响应；云端推理用于高精度分析。双模切换是企业边缘计算的标准架构。

### 三种切换方式

1. **手动切换**：Qt 界面按钮 / `hubctl inference cloud|local`（经 IPC）
2. **配置切换**：`inference.backend` 配置项，重启生效
3. **自动降级**（企业级亮点）：

```
cloud_engine 心跳检测（默认 2s 一次）
    ├── 连续 3 次心跳失败（约 6s）→ 自动切换 local_engine
    ├── 云端恢复（心跳成功）→ 自动切回 cloud_engine
    ├── 切换时通知界面与告警服务（事件上报）
    └── 切换不中断采集（仅切换推理后端，帧流持续）
```

### cloud_engine 实现要点

```
板端：采集帧 → 缩放(640x480) → JPEG 编码(质量85, ~30-80KB)
     → TCP 发送（长度前缀协议）
PC：  解帧 → YOLOv8 GPU 推理 → 结果 JSON → TCP 回传
板端：解析结果 → 统一 det_result_t → 界面叠加 + 告警判定
```

**延迟预算**（局域网）：帧上传 ~5ms + GPU 推理 YOLOv8n 15-30ms + 回传 ~1ms ≈ 30-60ms/帧 → 理论 15+ FPS（受板端采集/编码限制约 10-15 FPS）。

**帧率自适应**：按实测往返延迟动态调整上传帧率（延迟 >200ms 降到 5 FPS），避免积压。

### local_engine 实现要点

```
NCNN 交叉编译（armv7, Cortex-A7 优化）
模型：MobileNet-SSD 人形检测（或 RetinaFace 人脸）
量化：FP16 / INT8（INT8 需校准集，可后续做）
部署：模型文件放 /opt/models/，初始化加载
优化：采集与推理流水线重叠（双线程）、推理线程绑定
目标：1-5 FPS，CPU 占用可控
```

### 对比报告（P5 阶段交付物）

实测记录：精度（mAP/误检率）、帧率、CPU 占用、内存、延迟——输出"边缘 vs 云端"决策文档。

### U-Boot 启动逻辑（脚本段）

```sh
# u-boot 启动脚本伪代码
if boot_attempts >= boot_max_attempts; then
    # 启动失败次数超限，回滚
    setenv boot_partition 其他分区
    saveenv
    boot from other
else
    increment boot_attempts
    saveenv
    boot from boot_partition
fi
```

核心流程（`v4l2_capture.c`）：

```c
/* 初始化序列 */
fd = open(dev, O_RDWR);
struct v4l2_format fmt = { .type = V4L2_BUF_TYPE_VIDEO_CAPTURE };
fmt.fmt.pix.width = w; fmt.fmt.pix.height = h;
fmt.fmt.pix.pixelformat = pixfmt;                    /* V4L2_PIX_FMT_YUYV */
ioctl(fd, VIDIOC_S_FMT, &fmt);

struct v4l2_requestbuffers req = { .count = 4, .type = V4L2_BUF_TYPE_VIDEO_CAPTURE,
                                   .memory = V4L2_MEMORY_MMAP };
ioctl(fd, VIDIOC_REQBUFS, &req);
for (i = 0; i < 4; i++) {
    struct v4l2_buffer b = { .type = ..., .memory = ..., .index = i };
    ioctl(fd, VIDIOC_QUERYBUF, &b);
    mmap(NULL, b.length, PROT_READ|PROT_WRITE, MAP_SHARED, fd, b.m.offset);
    ioctl(fd, VIDIOC_QBUF, &b);
}

/* 采集循环 */
ioctl(fd, VIDIOC_STREAMON, &type);
ioctl(fd, VIDIOC_DQBUF, &buf);   /* 取帧 */
memcpy/处理...
ioctl(fd, VIDIOC_QBUF, &buf);    /* 归还 */
```

`server.py` 核心结构：

```python
import socket, threading, struct, json
import numpy as np
import cv2
from ultralytics import YOLOv8

model = YOLOv8("yolov8n.pt")   # CPU 兜底；GPU 用 model = YOLOv8("yolov8n.pt").to("cuda")

def handle(conn):
    while True:
        hdr = conn.recv(8)                       # 帧头：len(4B,大端) + magic(4B)
        if len(hdr) < 8: break
        (length, magic) = struct.unpack(">II", hdr)
        if magic != 0x4652414D: break            # 'FRAM'
        data = recv_exact(conn, length)
        jpg = cv2.imdecode(np.frombuffer(data, np.uint8), cv2.IMREAD_COLOR)
        results = model(jpg, verbose=False)      # 推理
        boxes = []
        for r in results:
            for b in r.boxes:
                x1,y1,x2,y2 = map(int, b.xyxy[0].tolist())
                cls = model.names[int(b.cls)]
                conf = float(b.conf)
                boxes.append({"cls": cls, "conf": conf, "x":x1,"y":y1,"w":x2-x1,"h":y2-y1})
        resp = json.dumps({"ok": True, "boxes": boxes}).encode()
        conn.sendall(struct.pack(">II", len(resp), 0x52455350))  # 'RESP'
        conn.sendall(resp)

srv = socket.socket(); srv.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
srv.bind(("0.0.0.0", 9000)); srv.listen(4)
while True:
    c, _ = srv.accept()
    threading.Thread(target=handle, args=(c,), daemon=True).start()
```

## 4.13.4 双模切换引擎（核心）

`src/inference/inference_engine.h`：

```c
typedef struct inference_backend {
    int  (*init)(void *cfg);
    int  (*infer)(const uint8_t *rgb, int w, int h, det_result_t *out, int cap);
    void (*destroy)(void);
} inference_backend_t;

/* 双模调度器 */
typedef enum { BACKEND_CLOUD, BACKEND_LOCAL } backend_id_t;

typedef struct {
    backend_id_t mode;              /* 用户配置：cloud / local / auto */
    const inference_backend_t *cloud;
    const inference_backend_t *local;
    /* 健康状态 */
    int64_t last_cloud_ok_ms;
    int     cloud_fail_streak;
    int     local_fail_streak;
    /* 阈值 */
    int64_t cloud_degrade_ms;       /* 云端超时阈值，默认 6000ms */
} dual_backend_t;

/* 核心：auto 模式下的降级/恢复逻辑 */
static backend_id_t pick_backend(dual_backend_t *d)
{
    if (d->mode == BACKEND_CLOUD) return BACKEND_CLOUD;
    if (d->mode == BACKEND_LOCAL) return BACKEND_LOCAL;
    /* auto：云端最近成功在阈值内 → cloud，否则 local */
    return (now_ms() - d->last_cloud_ok_ms < d->cloud_degrade_ms)
           ? BACKEND_CLOUD : BACKEND_LOCAL;
}
```

**降级策略（Auto 模式）**：
1. 云端连续 3 次超时/失败 → 切本地，同时保持后台探测云端
2. 云端恢复（探测成功）→ 切回云端
3. 每次切换：log + 事件上报 MQTT（`{"event":"inference_backend_switch","from":"cloud","to":"local","reason":"timeout"}`）

## 4.14.5 板端 ota_service 实现

`apps/gatewayd/ota_service.c` 流程：

```
1. 心跳中携带当前版本 → 云端返回最新版本
2. 版本不一致 → 触发升级：下载升级包到 data 分区（校验 SHA256 + 签名）
3. 校验通过 → 写入备用分区（boot_b/rootfs_b 或对端槽）
4. 写 U-Boot 环境：update_pending=1, active_slot=切换
5. reboot → U-Boot 从新槽启动
6. 新系统启动 → 应用健康检查通过 → 上报 ok → 正式切换完成
7. 失败：boot_count 超限 → U-Boot 回滚到旧槽
```

### 5.3.2 代码规范

- 遵循 Linux kernel coding style（checkpatch.pl 零告警为目标）

```c
#define EDT_CAPTURE_ABI_VERSION  2U
#define EDT_CAPTURE_MAX_CHANNELS 8U

#define EDT_CAPTURE_EDGE_RISING   (1U << 0)
#define EDT_CAPTURE_EDGE_FALLING  (1U << 1)
#define EDT_CAPTURE_EDGE_BOTH     (EDT_CAPTURE_EDGE_RISING | EDT_CAPTURE_EDGE_FALLING)

/* 能力位 */
#define EDT_CAPTURE_CAP_NONBLOCK           (1U << 0)
#define EDT_CAPTURE_CAP_POLL               (1U << 1)
#define EDT_CAPTURE_CAP_EXCLUSIVE_OPEN     (1U << 2)
#define EDT_CAPTURE_CAP_MONOTONIC_TIMESTAMP(1U << 3)
#define EDT_CAPTURE_CAP_DROP_REASON_STATS  (1U << 4)
#define EDT_CAPTURE_CAP_INITIAL_SNAPSHOT   (1U << 5)
#define EDT_CAPTURE_CAP_RESET_STATS        (1U << 6)

/* 固定 16 字节事件记录 */
struct edt_capture_event {
    __u64 timestamp_ns;   /* 单调时钟纳秒 */
    __u32 sequence;       /* 全局递增序列号（乱序证据） */
    __u16 channel;        /* 通道号 0-7 */
    __u8  level;          /* 当前电平 0/1 */
    __u8  edge;           /* 边沿类型 0=unknown 1=rising 2=falling */
};

struct edt_capture_caps {   /* 48 字节 */
    __u32 abi_version;
    __u32 struct_size;
    __u32 event_size;
    __u32 max_channels;
    __u32 configured_channels;
    __u32 supported_edges;
    __u32 fifo_depth_events;
    __u32 flags;
    __u64 reserved[2];
};

struct edt_capture_config { /* 32 字节 */
    __u32 abi_version;
    __u32 struct_size;
    __u32 channel_mask;
    __u32 edge_mask;
    __u32 fifo_depth_events;
    __u32 flags;
    __u32 reserved[2];
};

struct edt_capture_stats {  /* 104 字节，可守恒统计 */
    __u32 abi_version;
    __u32 struct_size;
    __u32 running;
    __u32 fifo_level_events;
    __u32 fifo_capacity_events;
    __u32 fifo_high_watermark;
    __u32 last_sequence;
    __u32 reserved0;
    __u64 irq_events;           /* 进入 IRQ 次数（running 且通道使能） */
    __u64 queued_events;        /* 成功入队（边沿 + 初始快照） */
    __u64 read_events;          /* 用户态读取 */
    __u64 dropped_events;       /* 丢弃总数（溢出 + 采样错误） */
    __u64 wake_signals;         /* 空→非空唤醒信号次数 */
    __u64 fifo_overflow_events; /* FIFO 满丢弃 */
    __u64 sample_error_events;  /* GPIO 电平读取失败 */
    __u64 snapshot_events;      /* START 初始快照 */
    __u64 cleared_events;       /* 显式清空 */
};

#define EDT_IOC_MAGIC 'E'
#define EDT_IOC_GET_CAPS    _IOR(EDT_IOC_MAGIC, 0x00, struct edt_capture_caps)
#define EDT_IOC_START       _IO(EDT_IOC_MAGIC, 0x01)
#define EDT_IOC_STOP        _IO(EDT_IOC_MAGIC, 0x02)
#define EDT_IOC_SET_CONFIG  _IOW(EDT_IOC_MAGIC, 0x03, struct edt_capture_config)
#define EDT_IOC_CLEAR_FIFO  _IO(EDT_IOC_MAGIC, 0x04)
#define EDT_IOC_GET_STATS   _IOR(EDT_IOC_MAGIC, 0x05, struct edt_capture_stats)
#define EDT_IOC_RESET_STATS _IO(EDT_IOC_MAGIC, 0x06)
```

## 5.5 ★摄像头驱动设计：OV5640 V4L2 subdev

### 5.5.1 架构认知（imx6ull 摄像头双层驱动）

```
OV5640 sensor（I2C 0x3c）                    imx6ull CSI 控制器
┌──────────────────────────┐  8-bit 并行     ┌──────────────────────────┐
│ v4l2_subdev 驱动          │  CSI 总线       │ 采集平台驱动               │
│ (本项目开发)               │───media───────▶│ (mxc_v4l2_capture        │
│ s_stream/s_set_fmt/       │   endpoint      │   内核已提供，本项目分析)  │
│ enum_frame_interval       │   bus-width=8   │ /dev/video1             │
└──────────────────────────┘                 └──────────────────────────┘
```

**学习价值**：sensor 驱动是 V4L2 生态中最常见的"自研驱动"场景（不同 sensor 芯片都要写 subdev），CSI 控制器一般由 SoC 厂商提供——所以**重点自研 sensor 侧，分析控制器侧**。

### 5.5.2 实现计划（重构 mainline ov5640.c 精简版）

mainline `ov5640.c`（约 3800 行）包含大量可选模式，本项目**重写为学习版**（约 800-1200 行），保留核心架构：

```
ov5640/
├── ov5640.c               # 驱动主体
├── ov5640_regs.h          # 寄存器初始化序列表（裁剪关键模式）
├── ov5640.h               # 内部结构体
├── Makefile / Kconfig
├── dts/ov5640.dtsi        # 设备树节点
└── test/v4l2_app/         # 用户态采集测试
```

**v4l2_subdev_ops 结构**：

```c
static const struct v4l2_subdev_ops ov5640_subdev_ops = {
    .core   = &ov5640_core_ops,    /* s_power / s_gpio */
    .video  = &ov5640_video_ops,   /* s_stream / s_fmt / enum_frame_interval */
    .pad    = &ov5640_pad_ops,     /* get_fmt / set_fmt / init_cfg */
};
```

**关键技术点**：寄存器初始化序列（表格驱动）；电源/复位时序（pwn/rst-gpios 在 s_power 处理）；时钟 csi_mclk 24MHz；格式协商（YUYV/RGB565、enum_frame_size/interval）；media controller port/endpoint（bus-width=8）；帧间隔 15/30fps（寄存器表切换）。

`kernel/led/led_drv.c`：

```c
// SPDX-License-Identifier: GPL-2.0
#include <linux/module.h>
#include <linux/platform_device.h>
#include <linux/gpio/consumer.h>
#include <linux/miscdevice.h>
#include <linux/uaccess.h>
#include <linux/of.h>

#define LED_IOC_MAGIC 'L'
#define LED_IOC_ON    _IO(LED_IOC_MAGIC, 0x01)
#define LED_IOC_OFF   _IO(LED_IOC_MAGIC, 0x02)
#define LED_IOC_GET   _IOR(LED_IOC_MAGIC, 0x03, int)

struct led_dev {
    struct gpio_desc *gpio;
    int state;
    struct miscdevice misc;
};

static struct led_dev g_led;

static long led_ioctl(struct file *f, unsigned int cmd, unsigned long arg)
{
    switch (cmd) {
    case LED_IOC_ON:
        gpiod_set_value(g_led.gpio, 1);
        g_led.state = 1;
        return 0;
    case LED_IOC_OFF:
        gpiod_set_value(g_led.gpio, 0);
        g_led.state = 0;
        return 0;
    case LED_IOC_GET:
        return copy_to_user((void __user *)arg, &g_led.state, sizeof(int)) ? -EFAULT : 0;
    default:
        return -ENOTTY;
    }
}

static const struct file_operations led_fops = {
    .owner          = THIS_MODULE,
    .unlocked_ioctl = led_ioctl,
};

static int led_probe(struct platform_device *pdev)
{
    struct device *dev = &pdev->dev;
    int ret;

    /* gpiod 获取：设备树属性 "led-gpios"，GPIO_ACTIVE_LOW 由设备树表达 */
    g_led.gpio = devm_gpiod_get(dev, "led", GPIOD_OUT_LOW);
    if (IS_ERR(g_led.gpio))
        return PTR_ERR(g_led.gpio);

    g_led.misc.minor = MISC_DYNAMIC_MINOR;
    g_led.misc.name  = "led";
    g_led.misc.fops  = &led_fops;
    g_led.misc.parent = dev;
    ret = misc_register(&g_led.misc);
    if (ret)
        return ret;
    return 0;
}

static const struct of_device_id led_of_match[] = {
    { .compatible = "alientek,led" },
    {}
};
MODULE_DEVICE_TABLE(of, led_of_match);

static struct platform_driver led_driver = {
    .probe  = led_probe,
    .driver = {
        .name = "alientek-led",
        .of_match_table = led_of_match,
    },
};
module_platform_driver(led_driver);
MODULE_LICENSE("GPL");
```

# 5.11 P2 中断与事件：按键驱动

## 5.11.1 目标

- 掌握：设备树 + platform_driver + **IRQ 中断** + 等待队列 + poll
- 交付：按键事件上报驱动（阻塞 read / 非阻塞 read / poll 三种模式）

## 5.11.2 核心概念先修

- **中断下半部**：本项目事件入队用硬中断直接完成（操作简单），但需用 `spin_lock_irqsave` 保护（中断上下文不能睡眠）
- **等待队列**：进程阻塞在 `wait_event_interruptible`，中断里 `wake_up_interruptible`
- **poll**：`poll_wait` + 返回 POLLIN/POLLHUP

## 5.11.3 驱动源码骨架

`kernel/key_event/key_event.c`（单通道按键 → 事件上报）：

```c
// SPDX-License-Identifier: GPL-2.0
#include <linux/module.h>
#include <linux/platform_device.h>
#include <linux/gpio/consumer.h>
#include <linux/interrupt.h>
#include <linux/miscdevice.h>
#include <linux/poll.h>
#include <linux/wait.h>
#include <linux/uaccess.h>

#define KEY_EVENT_MAGIC 'K'
#define KEY_EVENT_CLEAR _IO(KEY_EVENT_MAGIC, 0x01)

struct key_event {
    __u64 timestamp_ns;
    __u8  key;
    __u8  pressed;   /* 1=按下 0=松开 */
} __packed;

struct key_dev {
    struct gpio_desc *gpio;
    int irq;
    /* 事件存储：P2 用简单的单事件槽 + 计数（P3 升级为 kfifo） */
    struct key_event last_event;
    atomic_t event_ready;      /* 1=有未读事件 */
    spinlock_t lock;
    wait_queue_head_t wq;
    struct miscdevice misc;
};

static irqreturn_t key_irq_handler(int irq, void *data)
{
    struct key_dev *k = data;
    int level = gpiod_get_value(k->gpio);
    unsigned long flags;

    spin_lock_irqsave(&k->lock, flags);
    k->last_event.timestamp_ns = ktime_get_ns();
    k->last_event.pressed = (level == 0);   /* 按下为低电平 */
    atomic_set(&k->event_ready, 1);
    spin_unlock_irqrestore(&k->lock, flags);

    wake_up_interruptible(&k->wq);
    return IRQ_HANDLED;
}

static ssize_t key_read(struct file *f, char __user *buf, size_t count, loff_t *off)
{
    struct key_dev *k = file->private_data;

    if (count < sizeof(struct key_event))
        return -EINVAL;

    /* 阻塞等待事件（O_NONBLOCK 则立即返回 -EAGAIN） */
    if (wait_event_interruptible(k->wq, atomic_read(&k->event_ready)))
        return -ERESTARTSYS;

    spin_lock_irqsave(&k->lock, flags);
    memcpy(&ev, &k->last_event, sizeof(ev));
    atomic_set(&k->event_ready, 0);
    spin_unlock_irqrestore(&k->lock, flags);

    if (copy_to_user(buf, &ev, sizeof(ev)))
        return -EFAULT;
    return sizeof(ev);
}

static unsigned int key_poll(struct file *f, poll_table *wait)
{
    struct key_dev *k = file->private_data;
    poll_wait(f, &k->wq, wait);
    return atomic_read(&k->event_ready) ? POLLIN : 0;
}

static int key_probe(struct platform_device *pdev)
{
    struct device *dev = &pdev->dev;

    k->gpio = devm_gpiod_get(dev, "key", GPIOD_IN);
    k->irq  = gpiod_to_irq(k->gpio);
    ret = devm_request_irq(dev, k->irq, key_irq_handler,
                           IRQF_TRIGGER_FALLING | IRQF_TRIGGER_RISING,
                           "key-event", k);
    /* ... miscdevice 注册 ... */
    return 0;
}

static const struct of_device_id key_of_match[] = {
    { .compatible = "alientek,key-event" }, {}
};
```

# 5.12 P3 ★企业级驱动：gpio_event 完整实现

> 项目 B 核心章节，对标设计文档第 5.4 节。实现顺序建议：**先单通道跑通 → 再扩多通道/kfifo → 再加统计/tracepoint/KUnit**。

## 5.12.1 数据流总览

```
GPIO 边沿 → IRQ handler → 时间戳+事件封装 → spin_lock → kfifo 入队
→ (空→非空) wake_up → read(): copy_to_user → 消费
        ↓
  原子统计计数（irq/queued/dropped/read...）可守恒验证
        ↓
  tracepoint（irq/enqueue/drop/read）→ ftrace 观测
```

## 5.12.2 数据结构

```c
/* 内部数据结构（与 UAPI 分离，UAPI 见 5.4.2） */
struct edt_capture_dev {
    struct device          *dev;
    struct gpio_descs      *gpios;        /* 通道 GPIO 数组 */
    struct gpio_desc       *const *desc;  /* gpiod_get_array 返回 */
    int                     num_chans;    /* 实际使能通道数 */
    unsigned long           channel_mask; /* 设备树声明的通道位图 */
    struct kfifo            fifo;         /* 事件 FIFO（2 的幂） */
    spinlock_t              lock;         /* IRQ + 入队 + 读共用 */
    struct mutex            mutex;        /* 配置 ioctl 用 */
    wait_queue_head_t       wq;
    atomic_t                running;
    atomic_t                opened;       /* 独占打开 */
    atomic_t                removing;
    /* 统计（全部 atomic） */
    struct edt_capture_stats stats;
    struct miscdevice       misc;
    unsigned int            fifo_depth;
};
```

## 5.12.3 实现步骤（每步一个文件）

### 步骤 1：UAPI 头文件（先写，测试程序依赖它）

### 步骤 2：模块框架 + probe

```c
static int edt_capture_probe(struct platform_device *pdev)
{
    struct device *dev = &pdev->dev;
    struct edt_capture_dev *cap;
    struct gpio_descs *g;
    u32 fifo_depth = 0;

    g = devm_gpiod_get_array(dev, "capture", GPIOD_IN);
    if (IS_ERR(g)) return PTR_ERR(g);
    if (g->ndescs > EDT_CAPTURE_MAX_CHANNELS) return -EINVAL;
    /* 每个 GPIO 校验：gpiod_cansleep? 是 → 不能在硬中断采样，拒绝 */
    for (i = 0; i < g->ndescs; i++)
        if (gpiod_cansleep(g->desc[i]))
            return -EINVAL;

    /* 设备树 fifo-depth-events，无则默认 1024 */
    device_property_read_u32(dev, "fifo-depth-events", &fifo_depth);
    fifo_depth = fifo_depth ? fifo_depth : 1024;
    if (!is_power_of_2(fifo_depth)) return -EINVAL;

    cap = devm_kzalloc(dev, sizeof(*cap), GFP_KERNEL);
    cap->gpios = g;
    cap->fifo_depth = fifo_depth;
    kfifo_init(&cap->fifo, NULL, fifo_depth * sizeof(struct edt_capture_event));
    spin_lock_init(&cap->lock);
    mutex_init(&cap->mutex);
    init_waitqueue_head(&cap->wq);
    atomic_set(&cap->running, 0);
    atomic_set(&cap->opened, 0);
```

### 步骤 4：IRQ 处理 + 入队（正确性关键）

```c
static irqreturn_t edt_capture_irq_handler(int irq, void *data)
{
    struct edt_capture_dev *cap = data;
    int idx = /* 由 dev_id 传递 channel 号，或遍历匹配 irq */;
    unsigned long flags;
    bool wake = false;

    spin_lock_irqsave(&cap->lock, flags);
    if (atomic_read(&cap->running)) {
        struct edt_capture_event ev;
        ev.timestamp_ns = ktime_get_ns();
        ev.sequence = cap->stats.last_sequence + 1;
        cap->stats.last_sequence = ev.sequence;
        ev.channel = idx;
        ev.level = gpiod_get_value(cap->gpios->desc[idx]);   /* 硬中断安全（已校验cansleep） */
        ev.edge = /* 用 IRQ 类型记录：rising/falling */;

        cap->stats.irq_events++;
        if (kfifo_avail(&cap->fifo) >= sizeof(ev)) {
            kfifo_in(&cap->fifo, &ev, sizeof(ev));
            cap->stats.queued_events++;
            if (cap->stats.fifo_level_events < kfifo_len(&cap->fifo))
                cap->stats.fifo_level_events = kfifo_len(&cap->fifo);
        } else {
            cap->stats.dropped_events++;
            cap->stats.fifo_overflow_events++;
            trace_edt_capture_drop(ev.sequence, idx, kfifo_len(&cap->fifo));
        }
        /* 空→非空唤醒 */
        if (wake) {
            cap->stats.wake_signals++;
            wake_up_interruptible_poll(&cap->wq, EPOLLIN);
        }
        trace_edt_capture_irq(idx, ev.level, ev.timestamp_ns);
        trace_edt_capture_enqueue(ev.sequence, idx, kfifo_len(&cap->fifo));
    }
    spin_unlock_irqrestore(&cap->lock, flags);
    return IRQ_HANDLED;
}
```

> **设计取舍**：kfifo 满时仍消耗序列号——保证 `queued + dropped == irq` 守恒（可验证）。

### 步骤 5：read（staging 事务式消费）

```c
static ssize_t edt_capture_read(struct file *fp, char __user *buf,
                                size_t count, loff_t *off)
{
    struct edt_capture_dev *cap = file_to_cap(fp);
    struct edt_capture_event ev;
    unsigned long flags;
    ssize_t ret;

    if (count % sizeof(struct edt_capture_event))
        return -EINVAL;

    /* 运行停止但 FIFO 非空：允许读完存量后返回 0 */
    if (!atomic_read(&cap->running) && kfifo_is_empty(&cap->fifo))
        return 0;

    /* 非阻塞：无数据直接 EAGAIN */
    if (fp->f_flags & O_NONBLOCK) {
        if (kfifo_is_empty(&cap->fifo))
            return -EAGAIN;
    } else {
        ret = wait_event_interruptible(cap->wq,
                !kfifo_is_empty(&cap->fifo) || !atomic_read(&cap->running));
        if (ret) return -ERESTARTSYS;
        if (kfifo_is_empty(&cap->fifo)) return 0;   /* STOP 唤醒 */
    }

    /* 事务式：先 peek 到内核 staging，copy_to_user 成功后才消费 */
    spin_lock_irqsave(&cap->lock, flags);
    if (!kfifo_out_peek(&cap->fifo, &ev, sizeof(ev))) {   /* 可能被并发消费 */
        spin_unlock_irqrestore(&cap->lock, flags);
        return -EAGAIN;
    }
    spin_unlock_irqrestore(&cap->lock, flags);

    if (copy_to_user(buf, &ev, sizeof(ev)))
        return -EFAULT;

    spin_lock_irqsave(&cap->lock, flags);
    kfifo_out(&cap->fifo, &ev, sizeof(ev));
    cap->stats.read_events++;
    spin_unlock_irqrestore(&cap->lock, flags);
    trace_edt_capture_read(count / sizeof(ev), kfifo_len(&cap->fifo));

    return sizeof(ev);
}
```

### 步骤 7：START 初始快照（正确性关键）

```c
static int edt_capture_start(struct edt_capture_dev *cap)
{
    unsigned long flags;
    int i, ret;

    /* 防并发 START：CAS */
    if (atomic_cmpxchg(&cap->running, 0, 1) != 0)
        return -EBUSY;

    /* 冻结所有通道中断，读当前电平作为快照 */
    disable_irq(cap->irqs[0]);   /* 或逐通道 disable_irq */
    spin_lock_irqsave(&cap->lock, flags);
    for (i = 0; i < cap->num_chans; i++) {
        struct edt_capture_event ev = {
            .timestamp_ns = ktime_get_ns(),
            .sequence = ++cap->stats.last_sequence,
            .channel  = i,
            .level    = gpiod_get_value(cap->gpios->desc[i]),
            .edge     = 0,   /* 快照无边沿 */
        };
        if (kfifo_avail(&cap->fifo) >= sizeof(ev)) {
            kfifo_in(&cap->fifo, &ev, sizeof(ev));
            cap->stats.queued_events++;
            cap->stats.snapshot_events++;
        }
    }
    spin_unlock_irqrestore(&cap->lock, flags);
    enable_irq(cap->irqs[0]);
    wake_up_interruptible_poll(&cap->wq, EPOLLIN);
    return 0;
}
```

# 5.15 P6 input 子系统 + 工具链收尾

## 5.15.1 input 子系统按键驱动

`kernel/key_input/key_input.c`：

```c
#include <linux/input.h>

struct key_input_dev {
    struct gpio_desc *gpio;
    int irq;
    struct input_dev *input;
    int key_code;        /* 设备树指定：如 KEY_ARM=227 等 */
};

static irqreturn_t key_input_handler(int irq, void *data)
{
    struct key_input_dev *k = data;
    int val = gpiod_get_value(k->gpio);      /* 0=按下（低有效） */

    input_report_key(k->input, k->key_code, val ? 0 : 1);
    input_sync_key(k->input);
    return IRQ_HANDLED;
}

static int key_input_probe(struct platform_device *pdev)
{
    k->input = devm_input_allocate_device(dev);
    k->input->name = "imx6ull-gpio-keys";
    k->input->id.bustype = BUS_HOST;
    __set_bit(EV_KEY, k->input->evbit);
    input_set_capability(k->input, EV_KEY, k->key_code);
    ret = input_register_device(k->input);
    /* 申请 IRQ ... */
}
```

**设备树**：

```dts
key-input {
    compatible = "alientek,key-input";
    key-gpios = <&gpio1 18 GPIO_ACTIVE_LOW>;
    linux,code = <227>;        /* KEY_ARM，或按需 KEY_A/KEY_POWER */
    status = "okay";
};
```

**验证**：`evtest` 选择设备后按键，应看到 `KEY_ARM` 按下/释放事件流。

**自研 vs input 子系统对比文档**（`docs/driver-architecture-decision.md`）要求：

```
| 维度       | gpio_event（自研）       | input 子系统        |
|-----------|-------------------------|--------------------|
| 接口       | 自定义 UAPI              | 标准 input API      |
| 生态       | 自建工具链               | evtest/Qt/evdev 直接消费 |
| 适用场景   | 高精度时间戳/自定义事件    | 标准按键/事件输入     |
| 学习价值   | 完整驱动链路             | 子系统框架           |
结论：两者并存——采集高精度事件用自研，标准输入消费用 input。
```

## 5.15.2 SUMP / PulseView 逻辑分析仪

**架构**：

```
gpio_event 采集（8 通道边沿事件，高精度时间戳）
    → event_reconstructor：把"边沿事件流"重建成"固定采样率时间网格"
    → capture_source：统一数据源抽象（多后端）
    → sump_server：实现 SUMP 协议（TCP:9527）
    → PC PulseView 连接（SUMP/OLS 兼容）→ 波形 + 协议解码
```

**SUMP 协议要点**（`protocol/sump_server.c`）：

```
SUMP 命令字节（0x00=复位 0x01=运行 0x02=ID 0x04=设置采样...）
状态机：IDLE → WAIT_RUN → 采集 → 回传 8 通道样本流
样本打包：每个采样点打包为 (D0..D7) 位图，按通道→位映射
```

**使用流程**：

```bash
# 板端
sump_server --port 9527 --device /dev/edt_capture0
# PC PulseView → 添加 SUMP/OLS 兼容逻辑分析仪 → 连接板端 IP:9527
# 选择采样率/通道 → Run → 观察波形
# 高级：将 SPI/I2C 信号接入通道 → PulseView 协议解码（I2C 时序分析）
```

> **重要声明（写入文档）**：该方案是"边沿事件重建网格"，等效采样率受事件率限制，用于低速协议调试（I2C ≤ 400kHz / UART），**不是硬件全速采样逻辑分析仪**。

**验收**：
- [ ] PulseView 可连接并显示 8 通道波形
- [ ] 接入 I2C 信号（AP3216C 的 SDA/SCL）→ PulseView I2C 协议解码出寄存器读写
- [ ] 采集 1M 样本无丢包（状态统计守恒）

# 第 6 章 Git 分支 / 提交规范

## 6.1 仓库拓扑（本项目 4 个仓库）

| 仓库 | 路径（开发机） | 说明 |
|---|---|---|
| edge-ai-gateway | `~/imx6ull/edge-ai-gateway` | 项目 A：应用 + Qt + 云端 |
| imx6ull-drivers | `~/imx6ull/imx6ull-drivers` | 项目 B：内核驱动 + 工具链 |
| linux-imx6ull | `~/imx6ull/linux-imx6ull` | 内核源码（**只读上游**，改 dtb 用 patch 或独立 overlay） |
| buildroot | `~/imx6ull/buildroot` | Buildroot（**只读上游**，定制用 BR2_EXTERNAL 外部树） |

**原则**：上游仓库（内核/Buildroot）**不直接改**；定制内容放外部层（`dts/` 补丁、`BR2_EXTERNAL` 目录），保证可升级。自己代码库（前两个）严格执行本规范。

## 6.2 分支模型（轻量 Git Flow，适合单人/双线）

```
main（稳定，随时可演示）
  └── 每个里程碑（P1/P2/...）从 main 切出 feat 分支开发
       └── 完成验证后合回 main，打 tag
  └── hotfix 分支：线上问题直改（本项目=演示回归）
```

**分支命名规则**：

| 类型 | 命名 | 示例 |
|---|---|---|
| 功能开发 | `feat/<阶段>/<简述>` | `feat/p1/ipc-jsonrpc` |
| 修复 | `fix/<简述>` | `fix/fifo-overflow-counting` |
| 文档 | `docs/<简述>` | `docs/benchmark-methodology` |
| 重构 | `refactor/<简述>` | `refactor/v4l2-capture-errpath` |
| 里程碑 | `milestone/<pn>` | `milestone/p3`（收尾阶段集中整理） |

**双线隔离**：A 线（应用）与 B 线（驱动）分别在各自仓库，**不做 cross-repo 分支**。

## 6.3 提交规范（Conventional Commits）

### 格式

```
<type>(<scope>): <subject>

<body（可选，说明"为什么"）>

<footer（可选，关联 issue / 破坏性变更）>
```

### type 一览

| type | 用途 | 示例 |
|---|---|---|
| `feat` | 新功能 | `feat(p1): 实现 JSON-RPC 分发器` |
| `fix` | 修复缺陷 | `fix(gpio_event): 修复序列号在 FIFO 满时乱序` |
| `docs` | 文档 | `docs(p6): 更新基准方法学` |
| `refactor` | 重构（不改行为） | `refactor(capture): 提取 enqueue_event 便于 KUnit` |
| `test` | 测试 | `test(edt_capture): 增加守恒断言` |
| `build` | 构建系统 | `build: 增加 imx6ull 交叉工具链文件` |
| `chore` | 杂项 | `chore: 更新 .gitignore` |
| `revert` | 回滚 | `revert: 回滚 OTA 槽位切换逻辑` |

### scope 约定（保持小集合）

- A 线：`cfg` / `log` / `ipc` / `mqtt` / `v4l2` / `qt` / `inference` / `alert` / `ota` / `cloud`
- B 线：`gpio_event` / `ov5640` / `led` / `key` / `beep` / `ap3216c` / `icm20608` / `input` / `sump`

### 提交正文要点

- **subject**：祈使句、≤50 字符、不加句号
- **body**：说明**为什么**改（动机），不重复代码在做什么
- **破坏性变更**：`BREAKING CHANGE:` 明确标注（如 UAPI 结构变化）

### 提交示例

```
feat(gpio_event): 实现 START 初始快照冻结

disable_irq 期间批量读取各通道当前电平构造快照事件，
防止并发 IRQ 与快照交错导致用户态看到半快照。

BREAKING CHANGE: START 后 FIFO 首 N 条为快照事件，
read 端需按 edge=0 过滤。
```

## 6.4 提交粒度与频率

- **小步提交**：一个逻辑单元一个提交（可编译、可运行、可回退）
- **禁止**：`Update file`、`fix stuff`、混合无关改动的大提交
- **编译通过再提交**：提交前必须通过本阶段验收项（如 `-Werror`、KUnit）
- **实验性代码**：进分支不合并；`main` 永远保持可演示

## 6.5 里程碑 Tag 规范

| 里程碑 | Tag 格式 | 示例 |
|---|---|---|
| 阶段完成 | `P<阶段>-v<版本>` | `P3-v0.1.0` |

## 6.6 标准工作流

### 新功能开发流程

```bash
# 1. 从最新 main 切分支
```

### 双线协作点处理（跨仓库）

| 协作点 | 规则 |
|---|---|

| A 用 B 的 OV5640 驱动 | A 的 v4l2_capture 只依赖标准 V4L2 接口，不依赖 B 私有 API（保持解耦） |
